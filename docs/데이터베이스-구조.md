# 데이터베이스 구조 (초안)

응답은 브라우저 `localStorage`에 저장되고, 통계·연구 활용에 동의한 응답은 Supabase(PostgreSQL)에도 저장됩니다.
이 문서는 그 서버 데이터베이스의 구조입니다. 브라우저의 응답 레코드([응답-데이터-스키마.md](응답-데이터-스키마.md))를 그대로 옮길 수 있게 설계했습니다.
접속 정보는 `.env.local`의 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`에 넣습니다(공개 키만, git에는 올리지 않음).

## 전체 구조

```
factor_versions (배출계수 버전)
      │ 1
      │
      ▼ N
responses (응답 1건 = 계산 1번) ──1:1── response_answers (13개 항목 원본값)
      │                         ──1:0..1── feedback (만족도 4문항)
      │                         ──1:N── response_results (계산 결과 캐시, 선택)
```

| 테이블 | 내용 | 필수 |
|---|---|---|
| `factor_versions` | 배출계수 버전과 그 버전의 계수 값 전체 | ✔ |
| `responses` | 응답 1건의 메타 정보: 시각, 입력 방식, 학기, 동의, 거주 지역 | ✔ |
| `response_answers` | 간편 입력 원본값 (항목마다 열 하나) | ✔ |
| `feedback` | 결과 화면의 피드백 4문항 | ✔ |
| `response_results` | 계수 버전별 계산 결과. 집계 속도용 캐시 | 선택 |

## 테이블 정의

### ① `factor_versions` — 배출계수 버전

계수가 바뀌어도 옛 응답을 다시 계산할 수 있도록 계수 값 전체를 보관합니다.

```sql
CREATE TABLE factor_versions (
  version      text PRIMARY KEY,                 -- '2026.11-draft'
  status       text NOT NULL DEFAULT 'draft'
               CHECK (status IN ('draft', 'active', 'retired')),
  factors      jsonb NOT NULL,                   -- factors.js의 EF·COMMUTE·HOUSING 등 전체
  released_at  timestamptz,
  note         text
);
```

### ② `responses` — 응답

언제, 어떤 방식으로, 어떤 동의를 받고 입력했는지를 담습니다.

```sql
CREATE TABLE responses (
  id                uuid PRIMARY KEY,            -- 브라우저에서 만든 id를 그대로 사용
  client_id         uuid,                        -- 같은 브라우저의 재측정을 묶는 익명 id (선택)
  schema_version    smallint NOT NULL,
  factor_version    text NOT NULL REFERENCES factor_versions(version),
  input_mode        text NOT NULL CHECK (input_mode IN ('simple', 'detailed')),
  semester          text NOT NULL CHECK (semester ~ '^\d{4}-[12]$'),   -- '2026-2'
  started_at        timestamptz NOT NULL,
  completed_at      timestamptz NOT NULL,
  duration_sec      integer NOT NULL CHECK (duration_sec >= 0),
  consent_service   boolean NOT NULL CHECK (consent_service),  -- [필수] 동의 없이는 저장 불가
  consent_research  boolean NOT NULL,                          -- [선택] 통계·연구 활용
  consent_at        timestamptz NOT NULL,
  region            text,                        -- 결과 화면에서 나중에 입력 (set_profile)
  created_at        timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX ON responses (semester);
CREATE INDEX ON responses (client_id, completed_at);
```

### ③ `response_answers` — 간편 입력 원본값

항목마다 열을 하나씩 두고, 허용 값은 `CHECK`로 막습니다. 값의 범위는 [questions.js](../src/lib/carbon/questions.js)와 같습니다.

```sql
CREATE TABLE response_answers (
  response_id      uuid PRIMARY KEY REFERENCES responses(id) ON DELETE CASCADE,
  commute_days     smallint NOT NULL CHECK (commute_days BETWEEN 0 AND 7),
  commute_minutes  smallint CHECK (commute_minutes BETWEEN 5 AND 120
                                   AND (commute_minutes <= 30 OR commute_minutes % 5 = 0)),
  commute_mode     text CHECK (commute_mode IN ('walk','bike','bus','subway','car','taxi','moto')),
                                                 -- 통학 0일이면 NULL
  home_trips       text NOT NULL CHECK (home_trips IN ('none','semester','monthly','weekly','twicePlus')),
  flights          text NOT NULL CHECK (flights IN ('none','domestic','asia','long')),
  housing          text NOT NULL CHECK (housing IN ('family','alone','dorm','boarding','share')),
  household        smallint NOT NULL CHECK (household BETWEEN 1 AND 4),     -- 4 = 4명 이상
  cooling          smallint NOT NULL CHECK (cooling BETWEEN 1 AND 5),
  heating          smallint NOT NULL CHECK (heating BETWEEN 1 AND 5),
  meat             text NOT NULL CHECK (meat IN ('rare','low','mid','daily')),
  meals_out        smallint NOT NULL CHECK (meals_out BETWEEN 0 AND 14),
  clothes          smallint NOT NULL CHECK (clothes BETWEEN 0 AND 10),      -- 10 = 10개 이상
  parcels          smallint NOT NULL CHECK (parcels BETWEEN 0 AND 20),      -- 20 = 20건 이상
  reusable         text NOT NULL CHECK (reusable IN ('rarely','sometimes','often')),
  defaults_used    text[] NOT NULL DEFAULT '{}', -- 기본값 그대로 둔 슬라이더 키
  parcels_domestic smallint CHECK (parcels_domestic BETWEEN 0 AND 300), -- 자세히 입력: 국내 택배 월 건수
  parcels_overseas smallint CHECK (parcels_overseas BETWEEN 0 AND 100), -- 자세히 입력: 해외직구 월 건수
  detail           jsonb                         -- 자세히 입력 { values, opened } (펼쳐 보지 않았으면 NULL)
);
```

### ④ `feedback` — 피드백

결과 화면에서는 4문항을 모두 답해야 보낼 수 있으므로 모든 열이 `NOT NULL`입니다.

```sql
CREATE TABLE feedback (
  response_id   uuid PRIMARY KEY REFERENCES responses(id) ON DELETE CASCADE,
  understand    smallint NOT NULL CHECK (understand BETWEEN 1 AND 5),   -- 결과 이해도
  trust         smallint NOT NULL CHECK (trust BETWEEN 1 AND 5),        -- 결과 신뢰도
  intent        text NOT NULL CHECK (intent IN ('yes','maybe','no')),   -- 감축 행동 의향
  revisit       text NOT NULL CHECK (revisit IN ('yes','maybe','no')),  -- 재측정 의향
  submitted_at  timestamptz NOT NULL
);
```

### ⑤ `response_results` — 계산 결과 캐시 (선택)

집계를 빠르게 하려고 두는 테이블입니다. ③과 ①만 있으면 언제든 다시 만들 수 있습니다.

```sql
CREATE TABLE response_results (
  response_id     uuid REFERENCES responses(id) ON DELETE CASCADE,
  factor_version  text REFERENCES factor_versions(version),
  total_kg        numeric(8,1) NOT NULL,
  transport_kg    numeric(8,1) NOT NULL,
  housing_kg      numeric(8,1) NOT NULL,
  food_kg         numeric(8,1) NOT NULL,
  goods_kg        numeric(8,1) NOT NULL,
  computed_at     timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (response_id, factor_version)
);
```

## 보안 규칙 (RLS)

브라우저에는 공개 키만 들어가므로, 공개 키(`anon`)로는 **넣기만 되고 읽기는 안 되게** 합니다.
읽기 정책을 만들지 않았으므로 저장된 응답은 Supabase 대시보드에서만 볼 수 있습니다.

```sql
ALTER TABLE factor_versions  ENABLE ROW LEVEL SECURITY;
ALTER TABLE responses        ENABLE ROW LEVEL SECURITY;
ALTER TABLE response_answers ENABLE ROW LEVEL SECURITY;
ALTER TABLE feedback         ENABLE ROW LEVEL SECURITY;

CREATE POLICY "anon insert" ON responses        FOR INSERT TO anon WITH CHECK (true);
CREATE POLICY "anon insert" ON response_answers FOR INSERT TO anon WITH CHECK (true);
CREATE POLICY "anon insert" ON feedback         FOR INSERT TO anon WITH CHECK (true);
```

응답은 배출계수 버전을 참조하므로, 앱의 `FACTOR_VERSION`(`src/lib/carbon/factors.js`)이 바뀔 때마다 그 버전을 먼저 넣어야 합니다.

```sql
INSERT INTO factor_versions (version, status, factors, note)
VALUES ('2026.11-draft', 'active', '{}', 'v0.1 임시 계수');
```

### 거주 지역 저장 함수 `set_profile`

거주 지역은 결과 화면에서 응답보다 늦게 입력하므로 `responses`를 고쳐야 합니다.
공개 키에 UPDATE 권한을 주면 읽기 권한까지 필요해지므로, 대신 **응답 id를 알 때 지역 칸만 고칠 수 있는 함수**를 둡니다.
응답 id는 브라우저에서 만든 무작위 UUID라 그 응답을 만든 브라우저만 알고 있습니다.

```sql
CREATE FUNCTION set_profile(p_id uuid, p_region text)
RETURNS void
LANGUAGE sql
SECURITY DEFINER
SET search_path = public
AS $$
  UPDATE responses
  SET region = NULLIF(p_region, '')
  WHERE id = p_id AND consent_research;
$$;

REVOKE EXECUTE ON FUNCTION set_profile(uuid, text) FROM public;
GRANT EXECUTE ON FUNCTION set_profile(uuid, text) TO anon;
```

## 변경 이력 (이미 만든 DB에 실행할 SQL)

### 2026-11-04 · 대학·학과 항목 삭제

결과 화면에서 대학·학과 입력을 없앴습니다. 이미 테이블을 만들었다면 SQL Editor에서 아래를 **한 번에** 실행합니다.
옛 함수가 두 열을 쓰므로 함수를 먼저 지우고 열을 지운 뒤, 지역만 받는 함수를 새로 만듭니다.

```sql
BEGIN;

DROP FUNCTION IF EXISTS set_profile(uuid, text, text, text);

ALTER TABLE responses
  DROP COLUMN IF EXISTS university,
  DROP COLUMN IF EXISTS department;

CREATE FUNCTION set_profile(p_id uuid, p_region text)
RETURNS void
LANGUAGE sql
SECURITY DEFINER
SET search_path = public
AS $$
  UPDATE responses
  SET region = NULLIF(p_region, '')
  WHERE id = p_id AND consent_research;
$$;

REVOKE EXECUTE ON FUNCTION set_profile(uuid, text) FROM public;
GRANT EXECUTE ON FUNCTION set_profile(uuid, text) TO anon;

COMMIT;
```

- 이미 저장된 대학·학과 값은 함께 지워집니다. 남겨 두려면 먼저 `SELECT id, university, department FROM responses WHERE university IS NOT NULL OR department IS NOT NULL;`로 내려받아 두세요.
- 이 SQL을 실행한 뒤에는 바뀐 앱을 배포(push)해야 합니다. 그 사이 옛 사이트에서 들어온 응답은 지역 저장만 실패하고, 새 사이트가 열릴 때 다시 보냅니다.

### 2026-11-04 · 택배 국내/해외직구 건수

택배의 자세히 입력을 국내 택배와 해외직구로 나눴습니다. 두 값은 `detail` 열(jsonb)에도 들어가지만, 해외직구 비율 같은 집계를 바로 할 수 있도록 열로도 저장합니다.
자세히 입력하지 않은 응답은 두 열 모두 `NULL`이고, 이때 택배 건수는 간편 입력 `parcels` 열을 봅니다.

```sql
ALTER TABLE response_answers
  ADD COLUMN IF NOT EXISTS parcels_domestic smallint CHECK (parcels_domestic BETWEEN 0 AND 300),
  ADD COLUMN IF NOT EXISTS parcels_overseas smallint CHECK (parcels_overseas BETWEEN 0 AND 100);
```

- 이 SQL을 **앱 배포(push)보다 먼저** 실행해야 합니다. 열이 없는 상태에서 새 사이트가 응답을 보내면 입력값 저장이 실패하고, 열을 만든 뒤 그 결과 화면을 다시 열 때 저장됩니다.
- 집계 예: `SELECT sum(parcels_overseas)::float / nullif(sum(parcels_domestic + parcels_overseas), 0) AS 해외직구_비율 FROM response_answers WHERE parcels_domestic IS NOT NULL;`

## 앱이 보내는 순서

`src/lib/remote.js`가 결과 화면에서 아래 순서로 보냅니다. **통계·연구 활용에 동의한 응답만** 보내고, 동의하지 않은 응답은 브라우저에만 남깁니다.

1. `responses` → `response_answers` INSERT (결과 화면이 처음 열릴 때)
2. 거주 지역을 고르면 `set_profile` 호출 (0.8초 뒤)
3. 피드백을 보내면 `feedback` INSERT

어디까지 보냈는지는 브라우저의 응답 레코드 `remote`에 기록합니다. 네트워크 오류 등으로 실패한 단계는 다음에 그 결과 화면을 열 때 다시 보냅니다.
이미 들어간 행을 다시 보내면 중복 오류(`23505`)가 나는데, 이는 성공으로 처리합니다.

## 설계 원칙

- **답변은 열로 나눕니다.** JSON 하나에 통째로 넣지 않으면 "자취생의 냉방 평균", "통학 수단별 응답 수" 같은 집계를 SQL로 바로 할 수 있습니다. 잘못된 값도 DB에서 막힙니다. 자세히 입력은 문항마다 칸 구성이 달라 `detail jsonb`에 `{ "values": 문항별 값, "opened": 펼쳐 본 문항 }`으로 담습니다(값 구조는 [응답-데이터-스키마.md](응답-데이터-스키마.md)의 '`detail` 값'). 간편 입력 열에는 자세히 입력을 가장 가까운 칸으로 옮긴 값이 들어가므로, 간편 입력 열만으로 계산한 값과 `detail`까지 반영한 값을 비교할 수 있습니다.
- **결과값은 원본이 아닙니다.** README의 원칙대로 원본은 ③ `response_answers`이고, ⑤ `response_results`는 다시 만들 수 있는 캐시입니다. 계수 버전이 바뀌면 새 버전으로 ⑤에 행을 추가합니다.
- **응답보다 늦게 들어오는 값이 있습니다.** 피드백과 거주 지역은 결과 화면에서 입력합니다. 피드백은 `feedback`에 INSERT하고, 거주 지역은 `set_profile`로 `responses`를 고칩니다.
- **개인 식별 정보는 받지 않습니다.** 이름·이메일은 저장하지 않습니다. 재측정 추적에는 브라우저에서 만든 익명 `client_id`만 씁니다. 현재 앱에는 `client_id`가 없어서 따로 추가해야 합니다.

## 현재 응답 레코드와의 대응

| 현재 레코드 (camelCase) | DB |
|---|---|
| `id`, `schemaVersion`, `factorVersion`, `inputMode`, `semester`, `startedAt`, `completedAt`, `durationSec` | `responses`의 같은 이름 열 (snake_case) |
| `consent.service` / `.research` / `.agreedAt` | `responses.consent_service` / `consent_research` / `consent_at` |
| `profile.region` | `responses.region` (빈 문자열은 `NULL`) |
| `answers.*` | `response_answers`의 각 열 (`mealsOut` → `meals_out` 등) |
| `defaultsUsed` | `response_answers.defaults_used` |
| `detail` · `detailOpened` | `response_answers.detail` (`{ values, opened }`) |
| `detail.parcels.domestic` / `.overseas` | `response_answers.parcels_domestic` / `parcels_overseas` (자세히 입력하지 않았으면 `NULL`) |
| `feedback` | `feedback` 테이블 (`null`이면 행 없음) |

## 구축 전에 정할 것

1. **집계 공개 최소 응답 수 (예: 10건)**
   지역·학기·거주 형태 같은 값을 조합하면 응답이 적은 그룹에서는 개인이 특정될 수 있습니다. 관리자 집계 화면에서는 `HAVING count(*) >= 10`처럼 기준 미만인 그룹을 숨깁니다.
2. **단계별 이탈 로그 (MVP 7단계)**
   입력을 중간에 그만둔 사람은 응답 레코드가 생기지 않습니다. 이탈을 재려면 `input_events`(세션 id, 단계, 이벤트 종류, 시각) 같은 로그 테이블이 따로 필요하며, 계측 화면을 만들 때 추가합니다.
