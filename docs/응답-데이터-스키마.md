# 응답 데이터 스키마 (v3)

README의 '확장을 위해 미리 반영할 것'에 맞춰 설계했습니다.

- 결과값이 아니라 **원본 입력값**(`answers`)을 저장합니다. 배출계수가 바뀌면 같은 입력으로 다시 계산합니다.
- 응답마다 **배출계수 버전**(`factorVersion`)과 **입력 방식**(`inputMode`)을 기록합니다.
- **학기**(`semester`)를 기록해 재측정·변화 추적에 씁니다.
- 거주 지역은 결과 화면에서 받습니다(`profile.region`, 포인트 제도 안내용).

응답은 브라우저 `localStorage`의 `carboncalc:responses` 키에 배열로 저장합니다.
통계·연구 활용에 동의한 응답은 Supabase에도 보냅니다([데이터베이스-구조.md](데이터베이스-구조.md)). 피드백은 동의 여부와 관계없이 보냅니다. 어디까지 보냈는지는 레코드의 `remote`(`response`·`profile`·`feedbackAt`)에 기록합니다. 피드백은 결과 화면에서 다시 입력할 수 있고, 다시 보내면 `feedback`이 새 답으로 바뀝니다.
입력 중인 답변은 `carboncalc:draft`에 따로 저장되어, 새로고침해도 이어서 입력할 수 있습니다.

## 레코드 예시

```json
{
  "id": "3df8a438-101c-43fc-8aad-d90b3b0ba79d",
  "schemaVersion": 3,
  "factorVersion": "2026.11-draft",
  "inputMode": "detailed",
  "semester": "2026-2",
  "startedAt": "2026-11-04T01:13:28.912Z",
  "completedAt": "2026-11-04T01:14:31.186Z",
  "durationSec": 62,
  "consent": { "service": true, "research": false, "agreedAt": "2026-11-04T01:13:28.911Z" },
  "answers": {
    "commuteDays": 5, "commuteMinutes": 25, "commuteMode": ["bus", "subway"],
    "homeTrips": "monthly", "flights": "asia",
    "housing": "alone", "household": 1, "cooling": 4, "heatingType": "gas", "heating": 3,
    "meat": "daily", "mealsOut": 10,
    "clothes": 2, "parcels": 5, "reusable": "rarely"
  },
  "detail": {
    "commuteMinutes": { "km": 6.5 },
    "housing": { "elecBill": 30000, "elecUnit": "won", "gasBill": null, "gasUnit": "won" },
    "cooling": { "coolHours": 9, "coolMonths": 3 }
  },
  "detailOpened": ["commuteMinutes", "commuteMode", "housing", "cooling"],
  "defaultsUsed": ["clothes", "parcels"],
  "profile": { "region": "서울" },
  "feedback": { "interest": 3, "understand": 4, "ease": 5, "satisfaction": 4, "sufficiency": 3, "reuse": 4,
                "wish": "친구와 결과 비교하기", "submittedAt": "..." }
}
```

## 필드

| 필드 | 설명 |
|---|---|
| `schemaVersion` | 이 문서의 스키마 버전 |
| `factorVersion` | 응답 당시 배출계수 버전 (`src/lib/carbon/factors.js`) |
| `inputMode` | `simple`(간편만) · `detailed`(자세히 입력한 문항이 하나라도 있음) |
| `semester` | `YYYY-1`(3~8월) / `YYYY-2`(9~12월, 다음 해 1~2월) |
| `startedAt` · `completedAt` · `durationSec` | 입력 시작·완료 시각과 소요 시간 → 가설 1(1분 내외 완료) 측정 |
| `consent.service` | [필수] 서비스 이용 동의 |
| `consent.research` | [선택] 통계·연구 활용 동의. `false`인 응답은 집계에서 뺀다 |
| `answers` | 간편 입력 원본값 (아래 표) |
| `detail` | 자세히 입력한 문항별 값 (아래 '`detail` 값'). 있는 문항은 계산에서 `answers`보다 우선한다 |
| `detailOpened` | 자세히 입력을 펼쳐 본 문항 (값을 바꾸지 않았어도) → 가설 2('자세히' 펼침 비율) 측정 |
| `defaultsUsed` | 직접 바꾸지 않고 기본값 그대로 둔 답의 키(슬라이더, 냉방 `cooling`, 난방 `heatingType`·`heating`, 텀블러·다회용기 `reusable`) → 기본값 의존도 측정. `reusable`은 2026-11-10부터, `heatingType`은 2026-11-11부터 기본값이 있어 그 전 응답에는 들어 있지 않음 |
| `profile` | 거주 지역(포인트 안내용). 대학·학과는 2026-11-04에 없앴다(그전 레코드에는 빈 값으로 남아 있을 수 있음) |
| `feedback` | 1~5점: 계산 전 환경·기후 관심도(`interest`), 결과 이해도(`understand`), 입력 간편도(`ease`), 만족도(`satisfaction`), 정보 충족도(`sufficiency`), 재사용 의향(`reuse`) / 추가 기능 의견(`wish`, 선택·500자, 없으면 `null`) → 가설 1·3 측정. 2026-11-05 이전 레코드는 `understand`·`trust`·`intent`·`revisit` 형식 |

## `answers` 값

| 키 | 값 |
|---|---|
| `commuteDays` | 0~7 (주 통학 일수) |
| `commuteMinutes` | 5~30(1분 간격), 35~120(5분 간격) |
| `commuteMode` | `walk` `bike` `bus` `subway` `car` `taxi` `moto` 중 하나 이상의 **배열** (고른 수단을 같은 시간씩 탄다고 보고 계산) · 통학 0일이면 `null` 가능. v2 이하는 문자열 하나 |
| `homeTrips` | `none` `semester` `monthly` `weekly` `twicePlus` |
| `flights` | `none` `domestic` `asia` `long` |
| `housing` | `family` `alone` `dorm` `boarding` `share` |
| `household` | 1~4 (4 = 4명 이상) |
| `cooling` · `heating` | 1~5 = 하루 사용 시간 2·4·6·9·12시간 이상 (기본값 3). v2 이하는 주변과 비교한 정도(3 = 보통)였고, 계산은 같은 칸으로 다시 한다 |
| `heatingType` | `gas` `electric` `district` `unknown` (기본값 `unknown`). v2 이하에는 없고, 자세히 입력 `housing.heating`에 있을 수 있다 |
| `meat` | `rare` `low` `mid` `daily` |
| `mealsOut` | 0~14 (주 배달·외식 횟수) |
| `clothes` | 0~10 (10 = 10개 이상) |
| `parcels` | 0~20 (20 = 20건 이상) |
| `reusable` | `rarely` `sometimes` `often` |

## `detail` 값

자세히 입력을 펼치면 간편 입력값으로 정한 기본값이 보이고, **값을 하나라도 바꾸면** 그 문항의 모든 칸이 저장됩니다.
'간편 입력으로 되돌리기'를 누르면 그 문항이 `detail`에서 빠집니다. 통학 0일로 건너뛴 문항의 자세히 입력은 저장하지 않습니다.

간편 입력으로 나타낼 수 있는 문항은 자세히 입력한 값을 **가장 가까운 간편 입력 칸에도 반영**하므로, `answers`에는 반영된 값이 들어 있습니다
(예: 편도 12km·버스 → `commuteMinutes: 50`, 택배 30건 → `parcels: 20`, 동거 5명 → `household: 4`). 거주 형태의 전기·가스 요금(`housing`)은 간편 입력에 해당 칸이 없어 반영하지 않습니다.
계산은 `detail`이 있는 문항에서 `detail`을 쓰고, '간편 입력만으로 계산한 값'은 `answers`만으로 계산합니다.
필드 정의와 기본값은 `src/lib/carbon/details.js`, 계산은 `src/lib/carbon/engine.js`의 `resolve()`에 있습니다.

| 문항 | 값 |
|---|---|
| `commuteDays` | `days`: 요일 배열 (0 = 월 … 6 = 일). 요일 수가 주 통학 일수 |
| `commuteMinutes` | `km`: 편도 거리 |
| `commuteMode` | `shares`: 수단별 비율(%) `{ walk, bike, bus, subway, car, moto }`, `fuel`: `gasoline` `diesel` `lpg` `hybrid` `ev`, `taxiPerMonth`: 택시 통학 월 횟수(편도). 간편 입력에는 비중이 있는 수단을 모두 반영 |
| `homeTrips` | `perYear`: 연 왕복 횟수, `mode`: `mixed` `train` `bus` `car` |
| `flights` | `domestic` · `asia` · `long`: 연 왕복 횟수 |
| `housing` | `elecBill`·`gasBill`: 월평균 요금 또는 사용량(없으면 `null`), `elecUnit`: `won` `kwh`, `gasUnit`: `won` `m3` (거주 형태는 그대로 쓰고 전기·냉난방·온수를 그 사용량에 맞춤) |
| `household` | `people`: 정확한 인원, `myShare`: 나의 에너지 부담 비율(%, 2명 이상일 때만, 비우면 `null` = 인원수로 똑같이 나눔) |
| `cooling` | `coolHours`: 하루 사용 시간, `coolMonths`: 사용 월수 |
| `heating` | `heatHours`: 하루 사용 시간, `heatMonths`: 사용 월수 (난방 방식은 간편 입력 `heatingType`) |
| `meat` | `beef` · `pork` · `chicken` · `fish`: 주 횟수 (0.5 단위) |
| `mealsOut` | `campus` · `out` · `delivery` · `convenience` · `cook`: 장소별 주 끼니 수 |
| `clothes` | `perMonth`: 월 구매 개수, `secondhand`: 중고 비율(%) |
| `parcels` | `domestic`: 국내 택배 월 건수, `overseas`: 해외직구 월 건수 (간편 입력 `parcels`에는 두 값의 합을 반영) |
| `reusable` | `drinks`: 주 테이크아웃 음료 잔수, `tumbler` · `deliveryReuse`: 텀블러·다회용기 비율(%) |

스키마 v1 레코드(자세히 입력 이전)는 `detail`이 없으며, 없는 것은 빈 객체로 봅니다.
스키마 v2 레코드는 냉난방이 한 문항이라 `detail.climate`(냉방·난방 시간과 요금)와 `detail.housing.heating`(난방 방식)을 씁니다. 계산할 때 `engine.js`의 `upgradeDetail()`이 지금 구조(`cooling` · `heating` · `housing` 요금)로 옮깁니다.
